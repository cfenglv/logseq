# Logseq Self-hosted RTC 2.0.2

这是自建 RTC 分支相对 2.0.1 的修复版本，重点解决长时间运行、网络代理和共享图谱编辑可靠性。

## 修复内容

- 修复共享图谱下载后，本地元数据事务提前创建 `created-by-ref` 用户、但没有把该用户上传到服务器，导致后续编辑持续收到 `tx/reject` 的问题。
- 对已经进入上述坏状态的客户端，在发送下一笔编辑时幂等补齐当前用户实体，无需删除或重新下载图谱。
- 单笔事务被服务端拒绝后继续处理队列，避免一个失败事务永久卡住后续本地修改。
- 增加 WebSocket 心跳、半开连接检测、网络恢复和 macOS/Windows 待机唤醒后的强制重连。
- 改进 macOS、Windows 和 Linux 的系统代理支持，包含 WebSocket 连接。
- 升级 Electron 到 42.4.1，包含 Safe Storage 初始化相关的上游修复，减少不必要的 macOS 钥匙串提示。
- GitHub Actions 同时构建 macOS x64/arm64、Windows x64/arm64 和 Linux x64/arm64，并生成 SHA-256 校验文件。

## 数据兼容性

本版本仍使用 `Logseq` 和 `com.logseq.logseq`，会继续读取已有 Logseq 用户目录、设置、登录态和本地图谱。请先退出旧客户端再安装，不要同时运行官方版和本 fork，并在升级前备份重要图谱。

已经显示为 rejected/failed 的旧事务不会被原样盲目重放，因为它们已经回滚；升级后进行的新编辑会触发用户实体自愈并正常进入同步队列。

## 已知限制

- 自建 RTC 仍处于实验性状态，重要数据必须单独备份。
- 无 Apple Developer ID 签名和公证的 macOS 构建仍可能被 Gatekeeper 拦截；Electron 更新不能替代公证。
- 固定本地签名只能稳定同一开发者机器上的钥匙串授权，无法让其他 Mac 自动信任。
- 所有协作者必须配置同一个 Sync Server URL，并使用兼容的客户端版本。

部署与客户端配置见 [自建 Logseq DB Sync / RTC](../selfhost-sync.md)。
