# Logseq Self-hosted RTC 2.0.1-selfhost.6

This release is a reliability update for self-hosted RTC. It repairs the
snapshot, checksum, reconnect, and client-state paths that could make a client
look synchronized even though a snapshot activation had failed or the local
database did not match the Worker. It also includes the Math editor lifecycle
and recovery improvements developed after `2.0.1-selfhost.5`.

## Updating from `.5`

`2.0.1-selfhost.5` is the first release on the fixed project-signing trust
chain. A correctly installed `.5` client can discover this stable `.6` release,
download the architecture-specific update, verify its signed manifest, and
install it through **Restart and install**. A manual replacement is not required
for `.5` to `.6`.

Before updating:

1. Back up important graphs and quit other Logseq processes.
2. Deploy the Worker bundled from this exact release to the existing
   self-hosted Worker, Durable Object, D1, and R2 resources.
3. In the `.5` client, check for updates and choose **Restart and install**.
4. On macOS, use **System Settings → Privacy & Security → Open Anyway** if
   Gatekeeper asks again for this new ad-hoc signed application bundle. Do not
   change certificate Trust Settings or remove quarantine attributes.
5. Confirm `2.0.1-selfhost.6` in Settings, open the same graph on two clients,
   and wait for both clients to report an open RTC connection with no pending
   operations.

Clients older than `.5` do not have this update trust chain. In particular,
macOS `.4` still requires the documented manual migration to `.5` or later.

## RTC client reliability

- Stops and quarantines the live RTC client before replacing a graph from a
  downloaded snapshot. A failed import or finalization can no longer leave the
  previous `open` state visible as a false synchronized state.
- Restores the durable graph and client-operation state after a failed snapshot
  activation, invalidates the old connection generation, and publishes a
  stopped or repair-required state instead of treating missing pending state as
  zero.
- Revalidates cached legacy and server-v2 checksums against one stable local
  database basis. Cache-only drift is repaired without being reported as graph
  corruption; a real database divergence still fails closed.
- Applies pulls, sidecar updates, cursor advancement, and checksum publication
  atomically. A failed remote apply does not advance the cursor or leave a
  partially repaired sidecar.
- Preserves one durable wire payload for a local transaction across lost-ACK
  reconnects. Retries keep the original transaction identity and E2EE marker,
  and historical retries are accepted only after authoritative checksum and
  marker verification.
- Keeps pending and in-flight operations until the corresponding validation and
  acknowledgement have settled, and prevents stale asynchronous writes from
  crossing a completed snapshot activation.

## Worker snapshot and transaction safety

- Validates snapshot roots, unique indexes, reference closure, required system
  metadata, checksums, and contiguous transaction history before publishing or
  accepting a snapshot.
- Repairs narrowly proven legacy built-in index tears while rejecting unknown,
  user-data, dangling-reference, or otherwise ambiguous corruption.
- Freezes legacy v1 snapshot generations lazily when a live write begins, so a
  download remains on one immutable basis without copying a healthy graph for
  every metadata request.
- Serializes snapshot activation behind outstanding legacy download leases and
  preserves active readers during timeout cleanup. Old fixed v1 URLs either
  finish on their reserved basis or fail before a response body begins.
- Makes upload receipts, staging cleanup, D1-ready projection, admin reset,
  transaction-log append, and connection publication atomic and restart-safe.
- Binds integrity attestations to all live KVS and critical checksum metadata
  mutations, including child-page address changes, without adding whole-graph
  validation to the healthy write path.
- Contains generic thenable, stream, base64, and R2 failure paths; cleanup is
  bounded, does not mask the original error, and does not delete a pre-existing
  direct-upload object after a failed overwrite.
- Preserves replayable legacy snapshots without `graph-created-at`: v2 returns
  the existing fallback signal, while v1 remains available after complete
  read-only index and history validation. Proven corruption still fails closed.

## Math editor reliability

- Makes property transitions to and from Math atomic and serializes overlapping
  type changes.
- Prevents pending Math commits from leaking through keyboard, pointer, picker,
  popup, CodeMirror, property-panel, navigation, copy, and renderer boundaries.
- Restores the previous committed editor state after a failed Math transition
  and keeps undo/redo, focus, and post-commit recovery on the same lifecycle.
- Adds the Math CodeMirror and interaction boundary suites to the formal release
  gate.

## Compatibility and safety

- Keeps the published `.1` through `.5` HTTP, pull, WebSocket, no-transaction-ID,
  and legacy snapshot wire shapes compatible. `.3` through `.5` continue to use
  v2 first and fall back to v1 only on the established unsupported response.
- Keeps the existing Worker identity, routes, Durable Object, D1, R2, graph
  data, and Sync Server URL. Deploy into the existing self-hosted resources; do
  not create a second production Worker for this upgrade.
- Self-hosted RTC remains experimental. Keep independent backups, and do not
  treat `open` plus zero pending operations as sufficient evidence if a download
  or checksum error is present.
