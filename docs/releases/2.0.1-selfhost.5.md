# Logseq Self-hosted RTC 2.0.1-selfhost.5

This release keeps the self-hosted RTC, updater, and compatibility contracts from `2.0.1-selfhost.4` while incorporating focused reliability fixes from the upstream Logseq DB line.

## Import and settings reliability

- Preserves the empty-string title fallback when a PDF annotation has no text or matching Markdown title, instead of importing a `nil` block title.
- Treats empty or whitespace-only Electron plugin settings files as an uninitialized file and loads the plugin's declared defaults. Malformed non-empty JSON still fails explicitly.

## Encryption dialogs

- Submits the password currently visible in both E2EE password dialogs. Password-manager and autofill updates that write the input element immediately are no longer lost because of delayed renderer state updates.

## Mobile graph downloads

- Allows a remote RTC graph to start downloading from the mobile graph switcher.
- Uses native bottom sheets for download progress on native mobile and a modal dialog on mobile web, with cleanup on both success and failure.
- Keeps the graph switcher popup mounted long enough for its action to start, then closes the mobile sidebar after the action is dispatched.
- Prevents Android bottom-sheet presentation from reentering while dismissal is restoring the shared WebView. The snapshot overlay now blocks touches while visible and releases them after the final snapshot is removed.
- Always acknowledges native bottom-sheet content readiness after dismissal, including when popup state was already cleared.
- Cancels queued bottom sheets when their action is closed, so dismissed download or menu content does not reopen after the native dismissal finishes.
- Recovers from native bottom-sheet presentation, dismissal, and toolbar failures so later mobile actions can still open and close normally.

## Test harness

- Makes the CLI sync-fixture unit tests resolve helper scripts from the actual `cli-e2e` root, independent of the shell's current working directory.

## Compatibility and deployment

1. Back up important graphs and quit every Logseq process.
2. Deploy the Worker from this release using the existing Cloudflare resources, Worker name, and Sync Server URL.
3. Install `2.0.1-selfhost.5`, or use **Settings → General → Check for updates** from `2.0.1-selfhost.4`.
4. Confirm `/health`, open the same graph on two clients, and wait for both pending counters to reach zero.

The client remains offline-first and retains the protocol compatibility of `2.0.1-selfhost.4`. Self-hosted RTC remains experimental, so keep independent backups of important data.

See [Self-hosted Logseq DB Sync / RTC](../selfhost-sync.md) for deployment and client configuration.
