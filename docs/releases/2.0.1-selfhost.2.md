# Logseq Self-hosted RTC 2.0.1-selfhost.2

This patch release improves long-running connection reliability, proxy compatibility, and shared-graph editing for the self-hosted RTC branch.

## Fixes

- Fixed a shared-graph initialization bug where a local metadata transaction created the `created-by-ref` user locally without uploading it to the server, causing later edits to be rejected with `tx/reject`.
- Added idempotent self-repair for clients already affected by the missing-user bug. The next edit uploads the current user entity without requiring the graph to be deleted or downloaded again.
- Continued processing the local queue after an individual server-rejected transaction so one failed transaction cannot permanently block later edits.
- Added WebSocket heartbeats, half-open connection detection, network recovery, and forced reconnection after macOS or Windows resumes from sleep.
- Improved system proxy support on macOS, Windows, and Linux, including WebSocket connections.
- Upgraded Electron to 42.4.1, which includes upstream Safe Storage initialization fixes and reduces unnecessary macOS Keychain prompts.
- Re-signed ad-hoc macOS bundles consistently and added a packaged-runtime smoke test to prevent `dyld` library-validation failures in GitHub-built apps.
- Added GitHub Actions builds for macOS x64/arm64, Windows x64/arm64, and Linux x64/arm64, with SHA-256 checksums.

## Data compatibility

This release continues to use the `Logseq` product name and `com.logseq.logseq` application ID, so it reads the existing Logseq user-data directory, settings, authentication state, and local graphs. Quit the previous client before installing, do not run official Logseq and this fork at the same time, and back up important graphs before upgrading.

Transactions already marked rejected or failed are not replayed blindly because they have already been rolled back. A new edit made after upgrading triggers the user-entity repair and enters the normal sync queue.

## Known limitations

- Self-hosted RTC remains experimental. Keep independent backups of important data.
- macOS builds without Apple Developer ID signing and notarization may still be blocked by Gatekeeper. Updating Electron does not replace notarization.
- A fixed local signing identity can stabilize Keychain authorization on one developer's Mac, but it cannot make other Macs trust the build automatically.
- Every collaborator must configure the same Sync Server URL and use a compatible client version.

See [Self-hosted Logseq DB Sync / RTC](../selfhost-sync.md) for deployment and client configuration.
